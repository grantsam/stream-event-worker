# Latency Benchmark

Monotonic timestamps use `process.hrtime.bigint()`:

- `t0`: event generated by the local harness (outside the internal recorder)
- `t1`: `event_received`
- `t2`: `validation_started`
- `t3`: `rule_match_completed`
- `t4`: `dedupe_completed`
- `t5`: `dispatch_started`
- `t6`: `dispatch_completed`

Reported internal metrics are `receive_to_match_ms` (`t1→t3`), `match_to_dispatch_ms` (`t3→t5`), and `receive_to_dispatch_ms` (`t1→t6`). The harness also measures an outer worker span around `RunningApp.process()`. A stage that is not reached is counted as missing rather than fabricated.

## Commands

```powershell
npm run benchmark -- --events 10000
npm run soak -- --duration 10m
```

Benchmark runs an exact positive number of sequential synthetic events. Soak runs until a monotonic deadline and accepts `ms`, `s`, `m`, or `h`; `Ctrl+C` produces an aborted summary after graceful shutdown. The event loop yields periodically so signals can be handled.

Each event uses a unique synthetic ID and a mutable epoch clock advanced beyond cooldown, keeping the full match/mock-dispatch path active without making wall-clock waits part of the measurement. One JSON summary reports:

- processed/generated/dispatch counts and correctness gaps/errors;
- decision and status counts;
- throughput based on monotonic elapsed time;
- nearest-rank p50/p95/p99 for all local spans;
- process RSS and heap-used start/end/peak samples.

Percentiles use the nearest-rank method over finite samples. Empty sample sets report `null`. Memory samples describe process observations during one run; they are not proof that no leak exists. Exact percentiles retain one numeric sample per event, so extremely long soaks should be bounded appropriately.

## Scope

Every summary is marked:

```json
{ "scope": "local_worker_mock_transport_only", "messengerE2e": false }
```

These values measure local computation and in-process mock dispatch only. They do not include Messenger delivery, server queues, encryption/decryption, acknowledgements, account behavior, or network time and must not be described as end-to-end Messenger latency.
